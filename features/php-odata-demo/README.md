# php-odata-demo — модуль Dolibarr `odatatest` поверх 1С OData

Второе демо к опубликованному стандартному OData 1С (первое — `features/odata-demo`,
страница на Node). Здесь: **генератор** модуля Dolibarr, который даёт список
документов 1С и редактор документа вместе с табличной частью.

PHP руками не пишется — только генерируется. Файлы в docroot редактировать нельзя.

## Запуск

```
features/php-odata-demo/scripts/phpinit.sh                    # composer, один раз
features/odata-demo/scripts/read-1c-odata-metadata.js         # метаданные 1С -> data/dbinfo.json
features/php-odata-demo/scripts/generate-odatatest-module.js  # генерация модуля
```

После генерации модуль нужно **выключить и включить** в админке Dolibarr:
права (`read`/`write`/`delete`) заводятся только при активации.

Предпосылки: поднят стенд (`a pm start --name qemu-win11-1c`), выполнен
`src/verbs/publish-1c-odata.js`, OData отвечает.

## Что где

```
data/gen-config.json5   единственный конфиг: список документов, колонки, поля
                        карточки, табличные части, пути, права модуля
data/dbinfo.json        машинный дамп метаданных 1С (аналог dobaerp/data/dbinfo.json)
src/pages/              колонки списка и поля карточки из метаданных
src/php/                генераторы PHP: обвязка, карточка, ajax-подсказка справочников
scripts/                оркестратор генерации
```

Переиспользуемые idiomlib-модули (`dol_table_layout`, `dol_row_source_sql`,
`dol_row_source_odata`, `dol_module`) больше не лежат здесь копией — они
влиты в dobaerp и берутся оттуда напрямую (см. `doc/merge-back.md`). Своей
версии этих файлов у нас больше нет: локальный `src/idiomlib/` был ровно тем
форком, который правила проекта запрещают, и его удалили, как только апстрим
дорос.

Подключение и секреты в конфиг генератора не дублируются: они берутся из
`data/1c-odata.json5` и состояния автосетапа.

## Проверки

```
node --test src/tests/php-odata-demo-generation.test.js   # манифест + php -l
```

Манифест обновляется осознанно: `ODATATEST_APPROVE=1 node --test src/tests/php-odata-demo-generation.test.js`.

## Ограничения

Существенная часть работы упёрлась в платформу и конфигурацию, а не в код.
Всё измеренное и воспроизведённое — в `doc/deferred-todo.md`; коротко:

* **`If-Match` игнорируется** — документированной оптимистической блокировки нет,
  сверка версии сделана приложением и неатомарна;
* **создание документов** через OData падает на `ОбработкаЗаполнения`;
* **`ПоступлениеТоваровУслуг`** отдаёт HTTP 500 на любое чтение, поэтому в демо
  четыре документа, а не пять;
* **запись перегенерирует номер**, если не передать `Number` явно, а при
  смене `Организация_Key` перегенерирует его ВСЕГДА, даже если `Number`
  передан явно — есть риск коллизии номера с другим документом;
* `$expand` не работает для одиночной сущности, а табличная часть — наоборот,
  читается только одиночной сущностью.

## Ссылочные поля (справочники)

Виджет выбирает генератор, а не рантайм: перед генерацией он спрашивает у 1С
`$count` по каждому справочнику, задействованному в карточках/таблицах
документов (`data/gen-config.json5#odata.selectMaxOptions`, по умолчанию
1000). Не больше порога — настоящий `<select>` + select2 (весь список виден
сразу, поиск внутри уже загруженного списка, идиома Dolibarr —
`Form::select_produits()`/`selectWarehouses()` в ветке, где
`PRODUIT_USE_SEARCH_TO_SELECT` выключен). Больше — запасной вариант,
текстовый инпут с ajax-автодополнением по вводу (`ajax_autocompleter()`,
идиома `Form::select_company()`) — тот же переключатель, которым сам
Dolibarr переходит на автодополнение для по-настоящему больших каталогов
товаров. На живой копии продакшена все четыре справочника демо (Организации,
Контрагенты, Склады, Номенклатура — от 3 до 459 записей) укладываются в
`<select>`.
